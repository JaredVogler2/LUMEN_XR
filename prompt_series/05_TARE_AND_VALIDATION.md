# 05 — Angular reference, usability, mock-panel measurement validation

Define interface to existing LUMEN browser app and Posit Connect; optional standalone browser prototype in app/ only if useful after CAD tasks, no App Store installation. Use HTTPS and explicit permission for DeviceMotion/DeviceOrientation; handle denied/unavailable/stale data, screen orientation changes and motion. Measure gravity-referenced signed inclination of the calibrated fixture X axis from 3D gravity vector, not screen roll subtraction blindly; static averaging, reject motion and sensor dropouts. Capture tare with X aligned to intended aircraft floor direction, same azimuth and polarity; if plane orientation matters or direction changes, scalar tare is insufficient—require additional reference geometry or mechanical alignment, not magnetometer assumptions. No sensor is validated by displaying extra decimals. Use calibrated reference angle and fixture offset; store timestamp, validity, reference direction, phone orientation, mounting revision. Browser demo can simulate sensor data but clearly label it. Green only if measured error plus uncertainty fits user-entered approved tolerance; otherwise show evaluation/unknown. No engineering tolerance invented. Audio/visual feedback optional. If app unavailable, conventional ruler and approved alignment method, no stale pass.

Mock-panel example: 13 in surface-following offset from left trim (flat or J-profile), 22 in down from top, 6x2 in rectangle, top-left anchor, floor-parallel edge. Confirm engineering interpretation before deployment. Use Oregon Rule or comparable low-tack marked tape only on mock; must independently approve adhesive, residue and dimension accuracy for actual panels. Physical tapes must be correctly oriented and registered, not assume crossed strips define arbitrary 3D surface. Confirm placement area flat. Procedure: measure/mark target, load fixture, tare floor direction, align pointer, rotate, stabilize, apply, release, inspect. Include liner management and no loose hardware. Mock validation matrix: flat/J origin, simulated pitch and roll, small/narrow/tall/large labels, label thickness variation, phone reseating, tape application variation, operator repeatability, release and force. Compare to calibrated inclinometer and independent reference ruler/fixture, measure endpoint errors, anchor error, angle, shift before/after release, time, damage, residue, failure count. Repeat across multiple operators, settings and sessions, propose initial 10 repeats per condition and justify a staged study. Record raw data, bias, repeatability, reproducibility, uncertainty terms (phone sensor, tare, jaw play, structural flex, standoff/parallax, tape, release). At 254 mm, 0.1° implies ~0.44 mm differential; report actual, not target. Stress mock cycles, inspect wear and clips; test fail-safe on phone power loss, latch release, dropped part, no sign-off. Define pre-use inspection, inventory and FOD checklist. Actual use requires employer EHS, manufacturing engineering, quality, IT and material/tool approvals; personal phone never handles real aircraft images. Never claim validation until physical results supplied.

## Phone saddle and case calibration
Measure the angular offset between the fixture's placard datum and the phone sensor axis with the actual case and saddle locked. Repeat removal/reinstallation and across case thicknesses; evaluate uneven case compression or taper and jaw slip under placement pressure. Re-tare after reseating or changing phone/case, and reject unstable readings. The fixture datum, not the phone/case exterior alone, is the calibrated reference. Verify the assembled fixture's tare edge can reach the approved floor reference in the intended direction.
